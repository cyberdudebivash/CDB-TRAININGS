# PY-M09 knowledge check (8 questions)

Formative: it checks understanding of the lesson and is **not** evidence of competence on its own (the independent lab is). The answer key is held by instructors and is not published.
Questions are generated from `quiz.yaml`; each is tied to a learning outcome.

| # | Outcome | Question | Options |
|---|---|---|---|
| Q1 | LO1 | `timeit.repeat` reports five timings of the same statement: 0.52, 0.50, 0.61, 0.50 and 0.55 seconds. Which value is the best estimate of what the statement itself costs, and why? | A) 0.50, the smallest: noise from the system only ever adds time. B) 0.54, the average: it uses all the measurements. C) 0.61, the largest: it is the cost you must plan for. D) 0.52, the first: later runs benefit from caches and are not representative. |
| Q2 | LO1 | A profile shows function `a` with tottime 0.01 s and cumtime 2.0 s, and function `b` with tottime 1.5 s and cumtime 1.5 s. Where do you look first for code to change? | A) In `a`: its cumulative time is the largest. B) In `b`: it spends 1.5 s in its own lines, which are the lines to change or avoid. C) In neither: tottime and cumtime are estimates and cannot be compared. D) In whichever function was written last. |
| Q3 | LO2 | A function takes 60 percent of a program's run. You make it ten times faster. What whole-program speed-up should you expect? | A) About 10 times. B) About 6 times. C) About 2.2 times: 1 / (0.4 + 0.6 / 10). D) About 1.6 times. |
| Q4 | LO2 | You replace a nested loop that scans a list by a dictionary lookup. The cProfile call count of the new version is slightly HIGHER and the program is 100 times faster. What explains it? | A) The profiler is wrong; the call count must fall when the program gets faster. B) The saving is in the comparisons inside the loop, which are not function calls and therefore not counted; the right metric is comparisons, statements or time. C) A dictionary lookup is a slower operation than a list scan. D) The new version is not equivalent to the old one. |
| Q5 | LO3 | `x = object(); sys.getrefcount(x)` prints 2 although only one variable refers to the object. Why, and what should you use to ask whether an object is still alive? | A) The interpreter keeps a hidden copy; use `id(x)` to check. B) The call's own argument is a temporary second reference; use a `weakref` to ask whether an object is still alive. C) Every object starts with a count of 2; use `gc.collect()` and look at the return value. D) Python counts the object once for the name and once for its type; use `sys.getsizeof`. |
| Q6 | LO4 | Which test of 'this function scales linearly' is least likely to fail on a busy CI machine while the code is unchanged? | A) `assert elapsed < 0.05` after one run on 20 000 items. B) Run it on n and on 4n items (each the best of several runs, taking milliseconds) and assert that the second takes less than 9 times as long as the first. C) `assert elapsed < 2 * elapsed_stored_in_a_file_from_last_week`. D) Run it once on 10 items and assert that it takes under a millisecond. |
| Q7 | LO4 | A speed test passes for the new version of a function. What must always accompany it? | A) A second speed test on a different machine. B) A test that the new version returns the same answers as the old one on random and awkward inputs, because the fastest function is the one that returns an empty list. C) A comment with the date of the measurement. D) A larger input. |
| Q8 | LO5 | Which function belongs in the *core* of a program (the part that only computes)? | A) `def load(path): ...` which opens a file and returns its lines. B) `def report(rows): print(...)`. C) `def top_users(attempts, n): ...` which turns a sequence of attempts into a ranked list. D) `def main(): ...` which parses the command line and exits with a code. |
