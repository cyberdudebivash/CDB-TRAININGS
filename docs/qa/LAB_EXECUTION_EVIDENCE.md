## 1. What this records

Execution of the Python Engineering labs (PY-M02, PY-M04, PY-M07) and of the module-pack checks that run every lesson code block and verify outcome traceability. Each interpreter row is a **fresh virtual environment** with the pinned toolchain from `courses/python-engineering/labs/requirements.txt`; the suites run with that environment's interpreter, and the lab tests start their own sub-processes with it, so the build, install, mutation and exploit steps ran on that Python version.

A lab is called *executed* here only for the interpreters listed below, in this environment, at the stated commit. It is not evidence of learner success, subject-matter correctness review, or behaviour on other operating systems.

## 7. Not verified by this evidence

- Windows and macOS (the shell-injection probe is POSIX-only; symbolic-link and file-mode checks differ).
- CPython releases not listed in section 3, including 3.10 and earlier (end of life) and any build other than the ones named.
- Installation of the lab toolchain from an index other than PyPI, or with different versions than the pins.
- Any learner's own solution; whether the quiz items discriminate; whether the time estimates are right (no learner pilot has been run).
- Subject-matter correctness: no SME review of lessons, labs or quizzes has taken place.
- Behaviour after 2026-10-14: the Stage B refresh has not been performed.

- **2026-10-14, CPython 3.12.3 (distribution package):** A first matrix run failed one check on this interpreter only: test_exploit_tls_context_verifies_certificates_and_names asserted ssl.SSLContext.minimum_version >= TLS 1.2, which the distribution's OpenSSL configuration reports differently than the other builds. The assertion about the minimum protocol version was removed from the check and from the lab README contract (it depended on platform configuration, not on the learner's code); certificate and host-name verification are still checked. The matrix was re-run on the committed tree.
