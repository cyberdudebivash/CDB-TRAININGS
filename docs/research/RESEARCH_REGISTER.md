## Findings and resulting changes

### R-001 - NIST SP 800-61 Rev. 3 - Incident Response Recommendations and Considerations for Cybersecurity Risk Management: A CSF 2.0 Community Profile

- **Finding:** Section 2.1 contrasts the previous (Rev. 2) life-cycle model with a model based on the six CSF 2.0 Functions (Govern, Identify, Protect, Detect, Respond, Recover). Table 1 maps the four Rev. 2 phases (Preparation; Detection & Analysis; Containment, Eradication & Recovery; Post-Incident Activity) to CSF 2.0 Functions. Rev. 3 does not define a six-phase lifecycle; Rev. 2 had four phases.
- **Resulting change:** Findings F-SOC-001; pilot unit text uses the NIST-accurate description and labels PICERL as a common practitioner model, not NIST.

### R-002 - NIST CSWP 29 - The NIST Cybersecurity Framework (CSF) 2.0

- **Finding:** The Respond (RS) function lists categories RS.MA (Incident Management), RS.AN (Incident Analysis), RS.CO (Incident Response Reporting and Communication) and RS.MI (Incident Mitigation). The identifier "RS.RP" does not occur anywhere in the CSF 2.0 document (0 matches).
- **Resulting change:** Finding F-SOC-002.

### R-003 - CERT-In Directions No. 20(3)/2022-CERT-In under section 70B(6) of the IT Act 2000

### R-087 - Requests - Quickstart (timeouts, redirects, raise_for_status, JSON decoding)

- **Finding:** The Timeouts section says "Nearly all production code should use this parameter in nearly all requests. Redirects are followed for all verbs except HEAD by default. r.json() success does not indicate a successful response; use raise_for_status() or check the status code.
