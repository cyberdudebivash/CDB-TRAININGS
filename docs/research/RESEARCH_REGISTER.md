## Findings and resulting changes

### R-001 - NIST SP 800-61 Rev. 3 - Incident Response Recommendations and Considerations for Cybersecurity Risk Management: A CSF 2.0 Community Profile

- **Finding:** Section 2.1 contrasts the previous (Rev. 2) life-cycle model with a model based on the six CSF 2.0 Functions (Govern, Identify, Protect, Detect, Respond, Recover). Table 1 maps the four Rev. 2 phases (Preparation; Detection & Analysis; Containment, Eradication & Recovery; Post-Incident Activity) to CSF 2.0 Functions. Rev. 3 does not define a six-phase lifecycle; Rev. 2 had four phases.
- **Resulting change:** Findings F-SOC-001; pilot unit text uses the NIST-accurate description and labels PICERL as a common practitioner model, not NIST.

### R-002 - NIST CSWP 29 - The NIST Cybersecurity Framework (CSF) 2.0

- **Finding:** The Respond (RS) function lists categories RS.MA (Incident Management), RS.AN (Incident Analysis), RS.CO (Incident Response Reporting and Communication) and RS.MI (Incident Mitigation). The identifier "RS.RP" does not occur anywhere in the CSF 2.0 document (0 matches).
- **Resulting change:** Finding F-SOC-002.

### R-003 - CERT-In Directions No. 20(3)/2022-CERT-In under section 70B(6) of the IT Act 2000

- **Finding:** Direction (ii): service providers, intermediaries, data centres, body corporates and Government organisations must report cyber incidents listed in Annexure I to CERT-In within 6 hours of noticing them or being brought to notice about them. The obligation is tied to Annexure I incident types, not to "critical" severity.
- **Resulting change:** Finding F-SOC-003.

### R-004 - LangChain 1.x import-path removal (reproduced)

- **Finding:** In a clean virtual environment, `from langchain.embeddings import OpenAIEmbeddings` raises ImportError; `from langchain.vectorstores import FAISS` and `from langchain.llms import OpenAI` raise ModuleNotFoundError. The audited RAG lab uses all three imports with an unpinned requirements list.
- **Resulting change:** Finding F-AI-001; lab status UNVERIFIED -> FAILING_ON_CURRENT_STACK until rebuilt with pinned, current packages.

### R-005 - Python Developer's Guide - Status of Python versions

- **Finding:** Supported: 3.11, 3.12, 3.13, 3.14, 3.15 (3.15 first released 2026-10-09). Python 3.10 reached end-of-life on 2026-10-01; 3.9 on 2025-10-31; 3.8 on 2024-10-07.
- **Resulting change:** Finding F-PYH-005; new courseware targets Python >= 3.11 and is tested on 3.13.

### R-006 - Python Packaging User Guide - Is setup.py deprecated?

- **Finding:** Using setup.py as a command-line tool is deprecated; commands such as install, develop, sdist and bdist_wheel "MUST NOT be run anymore". Recommended: pip for installs, `python -m build` for sdist/wheel, and a pyproject.toml [build-system] table.
- **Resulting change:** Finding F-PYH-003.

### R-007 - Eclipse Adoptium - Supported platforms / LTS release support

- **Finding:** LTS releases: Java 8, 11, 17, 21 and 25 (25 first available Sep 2025, supported at least to Sep 2031).
- **Resulting change:** Finding F-JAV-002. Oracle's own roadmap page returned HTTP 403 and was not read.

### R-008 - JUnit - current generation

- **Finding:** JUnit 6 is presented as the current generation and requires Java 17+. Release date not stated on the page.
- **Resulting change:** Finding F-JAV-002.

### R-009 - OWASP Top 10 for LLM Applications 2025

- **Finding:** LLM01 Prompt Injection; LLM02 Sensitive Information Disclosure; LLM03 Supply Chain; LLM04 Data and Model Poisoning; LLM05 Improper Output Handling; LLM06 Excessive Agency; LLM07 System Prompt Leakage; LLM08 Vector and Embedding Weaknesses; LLM09 Misinformation; LLM10 Unbounded Consumption.
- **Resulting change:** Findings F-AI-004, F-PYH-001 (LLM05/LLM06 map to eval() in an agent tool).

### R-010 - MITRE ATT&CK - version history / updates

- **Finding:** v20 is the current release as of the verification date. Courses should name the ATT&CK version they map to.
- **Resulting change:** Course content must pin the ATT&CK version (see pilot unit).

### R-011 - Web Content Accessibility Guidelines (WCAG) 2.2

- **Finding:** WCAG 2.2 adds nine success criteria over 2.1 (2.4.11, 2.4.12, 2.4.13, 2.5.7, 2.5.8, 3.2.6, 3.3.7, 3.3.8, 3.3.9) and removes 4.1.1 Parsing.
- **Resulting change:** Design system targets WCAG 2.2 AA (docs/architecture/DESIGN_SYSTEM.md).

### R-012 - ISC2 2024 Cybersecurity Workforce Study

- **Finding:** Global workforce gap estimated at 4,763,963 (+19.1% vs 2023). Survey of 15,852 professionals run with Forrester in Apr-May 2024; the workforce estimate excludes China and India.
- **Resulting change:** Findings F-SOC-005, F-OSINT-005: an 'India gap from ISC2' cannot come from this study; '3.5M' figures are not ISC2's 2024 number.

### R-013 - Licences of tools proposed for redistribution in the OSINT bundle

- **Finding:** theHarvester: GPL-2.0 only. recon-ng (lanmaster53): GPL-3.0. Sherlock: MIT. The licences of Maltego CE and SpiderFoot HX were NOT checked (NEEDS_VERIFICATION). The GitHub REST licence API returned HTTP 403 through the session proxy, so repository pages were read instead.
- **Resulting change:** Finding F-OSINT-002; docs/audits/IP_AND_LICENSE_REVIEW.md.

### R-014 - google-github-actions/auth README - authentication options

- **Finding:** "Workload Identity Federation is recommended over Service Account Keys"; service-account key JSON must be treated like a password and never expires by default.
- **Resulting change:** Finding F-GCP-001.

### R-015 - Google Cloud IAM - Best practices for managing service account keys

- **Finding:** Service account keys "can become a security risk if not managed carefully"; treat key use as an exception; use organization-policy constraints to block key creation. For organizations created on or after 2024-05-03 these constraints are enforced by default.
- **Resulting change:** Finding F-GCP-001 (key-based CI examples fail by default in newer organizations).

### R-016 - Google Cloud - Professional Data Engineer certification

- **Finding:** Exam assesses five areas: design data processing systems; ingest and process the data; store the data; prepare and use data for analysis; maintain and automate data workloads. 2 hours, 40-50 questions, USD 200, valid 2 years, recommended 3+ years industry / 1+ year on Google Cloud. The exam-guide PDF itself was not read.
- **Resulting change:** Finding F-GCP-004; certification alignment must be re-verified against the exam guide before it is claimed.

### R-017 - Google Cloud Storage docs - 'Discover object storage'

- **Finding:** The page uses only `gcloud storage` commands. It does not state whether gsutil is deprecated (status NOT verified).
- **Resulting change:** Finding F-GCP-004 records gsutil status as NEEDS_VERIFICATION.

### R-018 - datetime.datetime.utcnow() deprecation (reproduced)

- **Finding:** Under `python -W error`, datetime.datetime.utcnow() raises DeprecationWarning recommending timezone-aware now(UTC).
- **Resulting change:** Finding F-AI-003 (minor).

### R-019 - MITRE ATT&CK Terms of Use

- **Finding:** Non-exclusive, royalty-free licence to use ATT&CK for research, development and commercial purposes; copies must reproduce MITRE's copyright designation: "(c) 2026 The MITRE Corporation. This work is reproduced and distributed with the permission of The MITRE Corporation." Provided AS IS; ATT&CK is a registered trademark. Derivative-work terms not addressed.
- **Resulting change:** Every courseware page that reproduces ATT&CK content carries the notice (shared/templates/attribution-notices.md); IP review item IP-7.

### R-020 - SigmaHQ licences

- **Finding:** The SigmaHQ rules repository states its content is released under the Detection Rule License (DRL) 1.1; the DRL terms were not read. The Sigma specification repository's licence could not be determined from the page; the highest specification version mentioned there is 2.1.0.
- **Resulting change:** Pilot rules are original work and do not copy SigmaHQ rules; specification features are verified against the spec text before use.

### R-021 - Microsoft Learn - 4625(F) An account failed to log on (Windows 10 security auditing reference)

- **Finding:** Defines the 4625 fields (Logon Type, Account For Which Logon Failed, Failure Information Status/Sub Status, Network Information workstation and source address) and the logon-type table (2 Interactive, 3 Network, 4 Batch, 5 Service, 7 Unlock, 8 NetworkCleartext, 9 NewCredentials, 10 RemoteInteractive, 11 CachedInteractive). Documented Status values include 0xC0000064 (bad user name; several in a row can indicate user enumeration), 0xC000006A (bad password), 0xC000006D (bad user name or authentication information), 0xC0000072 (account disabled), 0xC0000193 (expired account), 0xC0000234 (account locked out). The page is an archived Windows 10 reference.
- **Resulting change:** Pilot lesson field and status tables; only documented status codes are used.

### R-022 - MITRE ATT&CK - T1110 Brute Force

- **Finding:** T1110 (Credential Access, TA0006) has sub-techniques T1110.001 Password Guessing, T1110.002 Password Cracking, T1110.003 Password Spraying, T1110.004 Credential Stuffing. Detection strategy DET0463 'Brute Force Authentication Failures with Multi-Platform Log Correlation' lists analytics AN1275-AN1279. The page summary did not describe the spraying/stuffing difference, so that explanation in the lesson is the course's own wording.
- **Resulting change:** Pilot lesson maps scenarios to T1110.001/.003 and cites the ATT&CK version; attribution notice added.

### R-023 - Sigma Rules and Correlation Rules Specifications

- **Finding:** Correlation rules are separate YAML documents with correlation.type (event_count, value_count, temporal, temporal_ordered), rules (by id or name), group-by, timespan (Xs/Xm/Xh/Xd) and a single-criterion condition (gt, gte, lt, lte, eq, neq; value_count adds `field`). Value modifiers include contains, startswith, endswith, all, exists, re, cidr and numeric lt/lte/gt/gte. Condition grammar: and/or/not, brackets, `1 of`/`all of` with patterns and `them`. pySigma 2.0.1 parses both rule kinds (executed).
- **Resulting change:** Pilot rules and the teaching evaluator (shared sigma_lite) follow this subset; unsupported features fail closed.
