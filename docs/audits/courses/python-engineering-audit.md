### F-PYH-001 (P0) Agent 'math tool' evaluates model-controlled input with eval()

- **p. 585:** `def math_tool(expr): return eval(expr)` in the agent tools example; no warning.
- **p. 586:** 'This is how ChatGPT Agents run.' (unsupported).

eval on LLM output is remote code execution through prompt injection (OWASP LLM05 Improper Output Handling / LLM06 Excessive Agency). It is taught as a pattern in a course that markets AI security.

*Reference R-009:* OWASP Top 10 for LLM Applications 2025 - OWASP GenAI Security Project, 2025 (verified 2026-10-14, method OFFICIAL_PAGE_SUMMARY).

**Verification:** MANUAL_READ. **Recommendation:** Replace with a restricted expression parser (e.g., ast-based allowlist) and teach the failure mode with a test.
**Remediation:** NOT_STARTED - Track PY-5.

### F-PYH-002 (P1) Automation examples teach insecure credential, TLS, SSH and shell patterns without warnings

- **p. 163:** servers.json inventory stores plaintext passwords (trivially guessable placeholder values).
- **p. 164:** paramiko `set_missing_host_key_policy(AutoAddPolicy())` - accepts any SSH host key (MITM risk).
- **p. 168:** Patch runner passes srv['password'] from the inventory.
- **p. 428:** requests with hard-coded credentials in auth= and verify=False for load-balancer APIs (also p. 427).
- **p. 269:** JWT signing secret hard-coded as a string literal.
- **p. 222:** Flask app.run(debug=True) (also p. 228).
- **p. 252:** Seed admin user created with a trivially guessable hard-coded password.
- **p. 373:** os.system(f"iptables -A INPUT -s {ip} -j DROP") (also p. 122: os.system with f-string host) - shell injection.

The scanner flagged 10 bare-except, 6 hard-coded secrets, 3 AutoAddPolicy, 2 verify=False, 2 debug=True, 4 weak default passwords, 2 os.system uses; each was read in context (some carry a one-line 'never store raw passwords' note, none shows the safe pattern).

**Verification:** STATIC_SCAN. **Recommendation:** Teach secrets via environment/secret managers, pinned host keys, TLS verification, subprocess without shell, and show insecure variants only as labelled anti-patterns with exploit tests.
**Remediation:** NOT_STARTED - Track PY-5.

### F-PYH-009 (P2) HTTP calls taught without timeouts or status checks; files opened without a context manager or an encoding; a destructive bulk-rename example

- **p. 125:** `requests.get("https://api.github.com/users")` then `print(res.json())` with no timeout and no status check (also pp. 91, 126, 135).
- **p. 129:** `async with httpx.AsyncClient() as client` is created inside the function that fetches one URL, so every call builds a new client.
- **p. 91:** Bulk rename `for i, file in enumerate(os.listdir()): os.rename(file, f"file_{i}.txt")` renames every entry of the current folder including the script itself, and silently replaces an existing file of the target name on POSIX.
- **p. 83:** `json.dump(data, open("file.json","w"))` and `json.load(open("file.json"))` leave the file handle to the garbage collector and pass no encoding (also pp. 90, 168).

Scan of the extracted text: 38 requests/httpx calls, one of them with a timeout (p. 336); 26 one-line open(...).read()/json.load(open(...)) patterns; 34 `with open(` uses; no `encoding=` argument anywhere. Executed (probe http-client-defaults, requests 2.34.2): against a server that never answers, requests.get(url) was still blocked after 3 s while a call with timeout=0.5 raised ReadTimeout; httpx defaults to a 5 s timeout. The scan counts come from regular expressions over extracted text, not from a person reading every page.

**Verification:** EXECUTED. **Recommendation:** Teach an explicit timeout on every request, status checking before decoding, one shared client, bounded retries for idempotent requests only, pathlib with a with-block or Path.read_text/write_text and an explicit encoding, and validation of decoded data against a schema.
**Remediation:** PLANNED_IN_TRACK - Module PY-M05 (courses/python-engineering/modules/PY-M05).

### F-PYH-010 (P2) Concurrency examples promise speed-ups without measurement and show unbounded, unsupervised asyncio patterns

- **p. 135:** ThreadPoolExecutor example for three URLs ends 'Result -> 3x faster execution with minimal effort' with no timing shown; the example calls requests.get without a timeout.
- **p. 136:** '1000 API calls': one AsyncClient is created per task, 1000 tasks run at once with no concurrency limit, no timeout and gather without error handling; the text says '1000 requests happen in SECONDS' and 'This is impossible with regular code'.
- **p. 134:** 'Python's GIL blocks CPU-bound threads but NOT IO-bound threads' is stated as the whole story; Python 3.14 officially supports free-threaded builds (R-046).
- **p. 177:** `pip install httpx asyncio`: asyncio is part of the standard library; the PyPI project of that name is a deprecated placeholder.
- **p. 178:** 'This can fetch 20 feeds in under 3 seconds' with asyncio.gather and no timing, limit or error policy.

Executed on CPython 3.11-3.15 (PY-M06 lesson): gather leaves sibling tasks running after one fails while TaskGroup cancels them (R-093); an unbounded fan-out of 60 requests put dozens of them in flight at once on the server (20 to 60 in the runs) while a semaphore of 5 kept the peak at 5; a blocking call inside a coroutine freezes every other task; threads do not speed up CPU-bound work on a GIL build. Probe pypi-asyncio-placeholder: pip install asyncio installs a code-free deprecated placeholder (R-094). The speed claims have no measurement in the source, so they are neither confirmed nor refuted; the module replaces them with a benchmark the learner runs.

**Verification:** EXECUTED. **Recommendation:** Choose threads, asyncio, processes or free-threading from a measured profile; bound concurrency; put a timeout on every call; use TaskGroup and asyncio.timeout; keep references to tasks; write benchmarks that report medians and variance and never state a speed-up that was not measured.
**Remediation:** PLANNED_IN_TRACK - Module PY-M06 (courses/python-engineering/modules/PY-M06).
